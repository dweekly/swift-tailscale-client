# Testing Strategy

How this package earns trust in an API surface that upstream labels unstable: spike against real daemons, unit-test the parsers against fixtures, and run integration tests against real daemons.

## Current release scope (2026-09-19)

Required CI is Apple-only: macOS tests and Thread Sanitizer, strict DocC, API
baselines, and iOS/tvOS/watchOS builds. The Linux/Headscale workflow below is
retained for manual experiments only; it is not scheduled or required for 1.0.
Linux compilation and runtime support are not qualified by this release.

## The spike-first rule

No endpoint is implemented from documentation alone. The sequence for every new surface:

1. **Spike against a real tailscaled.** Hit the endpoint directly and observe reality:
   ```bash
   # Unix socket (Homebrew/standalone daemon)
   curl --unix-socket /var/run/tailscaled.socket \
        -H "Host: local-tailscaled.sock" \
        http://local-tailscaled.sock/localapi/v0/status

   # Streaming endpoints
   curl --no-buffer --unix-socket /var/run/tailscaled.socket \
        -H "Host: local-tailscaled.sock" \
        "http://local-tailscaled.sock/localapi/v0/watch-ipn-bus?mask=1"
   ```
   Note status codes, headers (ETags!), transfer-encoding, empty bodies, and 204s — these are the things docs omit and tests must encode.
2. **Cross-check upstream source.** `ipn/localapi/` for the handler, `client/local/` for the Go client's request shape, `tailcfg`/`ipn` for types. The Go code is the contract; public docs lag it.
3. **Capture fixtures from the spike** (sanitized), never hand-typed from docs.
4. **Implement**, with the spike's corner cases written as tests first.

## Test harness architecture

### `TailscaleClientMocks` (shipped library product)

`MockTransport` and `RequestRecorder` are exposed via the public `TailscaleClientMocks` product that both our suite and downstream consumers use:

- **`MockTransport`** — scripted responses keyed by request matcher; records all requests.
- **Scripted streams** — `sendStreaming` yields a scripted sequence of lines with per-line delays, injected mid-stream errors, and controlled EOF, so the full `watchIPNBus` state machine (skip-bad-line, cancellation, reconnect) is unit-testable.
- **`RequestRecorder`** — actor capturing requests for assertion.
- **Fixture loaders** — shared helpers for the fixture library below.

Shipping mocks publicly is an adoption feature: apps depending on this package can test their own Tailscale-facing code without a daemon.

### Testable parsers

`HTTPWireFormat` and `ChunkedTransferDecoder` are dedicated internal types fed `Data` directly in unit tests via `@testable import`, separating wire framing from socket transport mechanics.

## Fixture library

```
Tests/TailscaleClientTests/Fixtures/
  *-sample.json              # single-endpoint samples
  LocalAPI/
    manifest.json            # index of versioned sets
    1.76.0/ 1.84.0/ 1.96.4/ 1.98.0/
    Oracle/
```

- The versioned sets under `LocalAPI/` are generated by `Scripts/capture-fixtures.py --synthetic`, so decoding tests can assert compatibility with each version's expected shape. They are not captured from those daemon versions; `LocalAPI/manifest.json` marks them `is_synthetic`. `capture-fixtures.py` does not contact a daemon.
- `capture-fixtures.py --sanitize-file` sanitizes keys, IPs, hostnames, and user identifiers in a raw response captured by hand.
- The only fixtures read from a real daemon are the `ping-captured-*.json` replies, recorded by `Scripts/capture-ping-fixture.py` with their source and digests in `ping-captured.provenance.json`. Use that script as the model for any new capture.
- `Documentation/endpoints.json` records, per endpoint, which of these kinds of evidence exist (`evidence.unit`, `evidence.live`, `evidence.historical`); `Scripts/generate-endpoint-docs.py --check` rejects a live claim that does not name its lane, run, daemon version, and date (negative tests in `Scripts/test-endpoint-evidence.py`).

## Corner-case checklist

Every transport/decoding change runs against this list; each item becomes a named test:

**Chunked transfer & HTTP framing**
- Chunk-size line split across two socket reads
- Chunk data split across reads; final `0\r\n\r\n` split across reads
- Trailers after the last chunk
- Response with no `Content-Length` and connection-close framing (HTTP/1.0 style)
- Streaming response with `Content-Length` (including 0) on a connection the server holds open: the body ends after that many bytes and the stream finishes; fewer bytes then EOF is a typed framing error (`StreamingBodyFramingSocketTests`, `HTTPWireFormatTests`)
- Status lines: 200 with empty body, 204 (e.g. `tka/modify`), 4xx/5xx with JSON and with plain-text bodies

**Streaming**
- Malformed JSON line mid-stream (must skip and report, not kill the stream)
- Oversized lines (>1 MB NetMap payloads)
- UTF-8 sequence split across read boundaries
- Stream cancellation mid-read; transport error mid-stream; server EOF
- Reconnect: backoff schedule, initial-state re-request, no event loss announcement

**Requests & errors**
- Timeout on connect and on read (`.timeout` error)
- 401/403 with and without auth token configured; auth header injection
- 404 on optional endpoints → `.endpointUnavailable` (with feature hint when `daemonFeatures()` has been called)
- `Host: local-tailscaled.sock` present on every request

**Decoding robustness (property/mutation tests)**
- Randomized truncation of every fixture must throw a typed error, never crash
- Random field deletion must either decode (optional field) or throw typed
- Unknown enum values decode to `.unknown(raw)` for every tolerant enum

## Coverage policy

- Coverage measured in CI (`swift test --enable-code-coverage` + `llvm-cov export`), with a hard floor enforced in `ci.yml` — no external service required. Codecov upload is a possible later addition for badges/patch checks.
- Floor: **85%** (raised at v0.12.0; 85.9% measured on macOS, driven by the CI report that names the worst-covered files). History: **55%** at v0.4.0 against a 56.8% baseline when `UnixSocketTransport` and `MacClientInfo` were integration-only; **70%** at v0.9.0 (~79% measured) after the parser extraction and streaming test rounds; **85%** at v0.12.0 via full-field model round-trips. The floor tracks under the measured value so regressions fail while honest measurement stays possible.
- Streaming path and transport parsers must reach full branch coverage — they are the historical blind spot (the v0.3.x headline features shipped untested).

## Integration testing

### Local (developer machines)

Unchanged: `TAILSCALE_INTEGRATION=1 swift test --filter TailscaleClientIntegrationTests` against whatever daemon is running locally. Env vars (`TAILSCALE_LOCALAPI_SOCKET`, etc.) select the target.

### Self-hosted macOS runner (live now, `integration.yml`)

The project has a self-hosted macOS runner with Tailscale installed and logged in, so the real-daemon integration suite runs in CI **today** — on pushes to main, same-repo PRs, and manual dispatch. Constraints that shape it:

- **Fork guard is mandatory.** Public repo + self-hosted runner means the workflow must never execute fork code; the job is gated on `github.event.pull_request.head.repo.full_name == github.repository`.
- **Read-only tests only.** The runner is attached to a real tailnet; the suite queries status/whois/ping/prefs/metrics and must not mutate daemon state. Write-API mutation tests (v0.8.0+) run exclusively in the hermetic headscale environment below.
- **Single version.** The runner tests whatever Tailscale version it has installed — valuable real-world signal, but not a version matrix.
- **Install-flavor aware discovery.** The workflow's "Configure LocalAPI access" step asks `tailscale debug local-creds` first — Tailscale's own discovery is authoritative for whatever flavor is installed. If the CLI is missing or its answer doesn't respond, it falls back through: unix sockets (Homebrew/standalone tailscaled), the standalone .pkg app (port from the `/Library/Tailscale/ipnport` symlink, token from the *contents* of the adjacent `sameuserproof-<port>` file — the runner user must be in the `admin` group to read it), then the App Store app (port and token encoded in the sameuserproof *filename* inside its Group Container — needs Full Disk Access). Every loopback candidate must answer an authenticated status request before it is used, because sameuserproof files from a previously installed flavor linger after switching and would otherwise be trusted blindly.

### Hermetic CI (Headscale in `integration-linux.yml`)

The self-hosted runner gives one real macOS daemon; the version matrix and mutation-safe environment need hermetic infrastructure, and *hosted* macOS runners can't run tailscaled — **Linux runners can**. Design:

- an `ubuntu-26.04` runner starts a `swift:6.1` container (the package's declared minimum toolchain) and boots **headscale** (open-source control plane) inside it
- installs real `tailscaled` from the pinned release tarball (or the unstable package track), runs it with `--tun=userspace-networking` (no root TUN needed)
- mints a pre-auth key locally against headscale, brings the node up
- runs `TailscaleClientIntegrationTests` over the daemon's unix socket with the write gate on, then `LoginLifecycleIntegrationTests` as a separate, final invocation
- `Scripts/ci-test-report.py --lane integration_linux_headscale` fails a lane on any failure or on any skip it does not list by test name, reason and (for endpoints older daemons lack) track

Why headscale rather than the real control plane: hermetic, no secrets, safe on fork PRs, free to create/destroy tailnets per run. A separate, optional monthly job with an ephemeral auth key (repo secret) can sanity-check against the production control plane.

**Version matrix:**

| Lane (track) | tailscaled | Headscale | Blocking |
|---|---|---|---|
| supported-floor | 1.76.0 | 0.28.0 | yes |
| intermediate-lts | 1.84.0 | 0.29.7 | yes |
| previous-stable | 1.102.5 (last 1.102.x) | 0.29.7 | yes |
| stable | 1.104.7 | 0.29.7 | yes |
| unstable | current unstable package | 0.29.7 | no (advisory drift signal) |

Headscale 0.29 rejects clients older than Tailscale 1.80, so the 1.76.0 lane runs 0.28.0, the last Headscale release that accepts it. That lane also starts `tailscaled` with `TS_CONTROL_IS_PLAINTEXT_HTTP=1`: without it, 1.76 redials control over TLS on port 443 within two minutes of its previous dial (as the login test does after logout), which the plain-HTTP headscale never answers. Expected skips on every lane: no peers to ping, no exit-node suggestion, no OS DNS in userspace mode, no STUN responses, Darwin-only interface discovery (three tests), and query-feature (headscale does not implement it). The 1.76.0 and 1.84.0 lanes also skip the endpoints those daemons do not serve (debug-optional-features, peer-by-id, dns-config, services, cert-domains), and 1.76.0 skips usermetrics, which it serves only with `TS_DEBUG_USER_METRICS` set.

The workflow is manual (`workflow_dispatch`) and outside release qualification since 2026-09-19; no other workflow calls it, and it is not a required check. Its last successful run on v0.12.0 code was 2026-09-20. On 1.x code it passed on all five lanes in [run 44980829674](https://github.com/dweekly/swift-tailscale-client/actions/runs/44980829674) (2026-11-22, commit `0a41f149e067`, tailscaled 1.76.0, 1.84.0, 1.102.5, 1.104.7, 1.105.361). That is an observation of those daemons under Headscale on Linux, not a statement that Linux is supported. Each release's notes state which daemon versions, if any, it was tested against.

### Testing against a specific daemon version (local, never in CI)

`Scripts/disposable-tailscaled.sh` builds a given upstream `tailscaled` release with `go install`, runs it as a throwaway userspace daemon with its own socket and in-memory state, and stops it again. The daemon is never logged in to a tailnet (it stays in `NeedsLogin`), which is enough for status, prefs reads, and IPN bus watch behavior. It does not touch the installed Tailscale: it never uses the default socket, and both scripts refuse any socket whose directory lacks the marker file the script writes. `stop` signals only the PID it started, and only if that process's command line still names the managed socket.

```bash
Scripts/disposable-tailscaled.sh v1.104.7 start         # build once (needs go), start, print version and BackendState
SOCK=$(Scripts/disposable-tailscaled.sh v1.104.7 sock)
TAILSCALE_LOCALAPI_SOCKET=$SOCK swift run tailscale-swift status
TAILSCALE_LOCALAPI_SOCKET=$SOCK swift run tailscale-swift watch
Scripts/watch-mask-probe.sh "$SOCK"                      # TSV: which watch-ipn-bus masks this version accepts (needs curl, jq)
Scripts/disposable-tailscaled.sh v1.104.7 stop
pgrep -fl tailscaled                                     # confirm only the system daemon (if any) remains
```

Binaries and run state go under `.build/disposable-tailscaled/` (override with `TSD_HOME`); the socket goes in a short `mktemp -d` directory under `$TMPDIR` (override with `TSD_SOCK_ROOT`) because macOS limits Unix socket paths to about 104 bytes. Several versions can run at once. The mask table in `watch-mask-probe.sh` copies the library and CLI default masks; keep it in step when those change.

### Mutation tests for write APIs (v0.8.0+)

Write endpoints (prefs PATCH etc.) get apply → verify → revert integration tests, run only in the headscale environment — never against a developer's real tailnet. They carry a second gate on top of `TAILSCALE_INTEGRATION=1`: `TAILSCALE_INTEGRATION_WRITE=1`, which only the headscale lane sets.

### Login-lifecycle test (v0.12.0)

`LoginLifecycleIntegrationTests` scripts the interactive auth flow end to end: `logout()` → `loginInteractive()` → catch `BrowseToURL` on the IPN bus → approve it with the headscale CLI (`headscale nodes register --user … --key <last URL path component>`) → wait for Running. Because it expires the node's keys mid-run, it stacks a **third** gate (`TAILSCALE_INTEGRATION_LOGIN=1`) and the headscale lane runs it as a separate, final `swift test` invocation so the main suite always talks to a logged-in daemon. `TAILSCALE_HEADSCALE_USER` overrides the headscale user it registers against (default `ci`). Never enable this gate outside a throwaway control plane.
