# swift-tailscale-client 1.1.0 Release Record

This is the record of what was run to qualify **1.1.0**. It was written before the `v1.1.0` tag was pushed, and tagging is the maintainer's decision. The nine tag-blocking results under "What blocks the tag" in the [1.1.0 release plan](../PLAN-1.1.0.md#what-blocks-the-tag) are recorded for the release commit in the release pull request, because a file in the tree cannot name the commit that contains it.

**Release pull request (nine results for the final commit):** [#63](https://github.com/dweekly/swift-tailscale-client/pull/63)

Everything below was run on commit `77fedf49b5012ddb06dca63ead357853ad1fa32f` (`77fedf4`, the merge of #62), the head of `main` when qualification began, unless a row says otherwise. Four changes landed after that commit: #61 (deterministic discovery-recovery tests and one shared rediscovery for concurrent requests), #64 (a deterministic watch overflow test), the change that added this record, the changelog section, and the version (#63), and #65 (newer CI artifact actions and Ubuntu runner image; no library, example, or documentation-site change). The release pull request records the results for the commit that contains all four. Each result is labeled verified, failed, or untested. Sanitized transcripts were kept outside the repository; every address and name below is a documentation placeholder.

## 1. Outcome

- **Verified on `77fedf4`:** hosted CI (`All Required Checks`), the self-hosted real-daemon Integration run, a first launch with every discovery override cleared on a standalone-Tailscale Mac, a disco ping to a real online peer classified the same way by the library and by the official CLI's rule, an initial watch notification from the real daemon, default watches and the sample's subscription against disposable Tailscale v1.102.2 and v1.104.7 daemons, the local repository checks, the deployed documentation site, and an agent's build of a fresh consumer resolved by SHA.
- **Failed:** none.
- **Untested:** live recovery (daemon restart, profile switch), the Mac App Store edition, a sandboxed caller, a logged-in 1.104+ daemon, the native discovery of a Unix-socket daemon, peer-relay and DERP replies observed live, and everything that happens after tagging (Swift Package Index, Homebrew, pilot feedback). Section 8 lists them with reasons.
- **Found during qualification and fixed in the same change as this record:** the guide's corrections from the agent trial (section 5.9), a wrong recovery suggestion for a missing socket, CI cancelling in-progress `main` runs, and stale live-evidence records in the endpoint manifest.

## 2. Scope

Apple platforms only: macOS 13+ runtime; iOS, tvOS, and watchOS build-only. Linux is unqualified. The release adds a typed ping path (`PingResult.path`, `PingPath`), four watch options, and the Peer Diagnostics sample, and fixes watches on current daemons. The API baseline is `v1.0.0` with an empty breakage allowlist.

## 3. What changed

See the [changelog](../../CHANGELOG.md#110---2026-11-21) for every change since 1.0.0 and the upgrade note. In short: `PingResult.path` says how a ping reached a peer with the official CLI's precedence; `isDirect` and peerAPI pings are corrected; watches work on Tailscale 1.104+, report a rejection at once, survive quiet periods on loopback, and rediscover a restarted daemon; the Peer Diagnostics sample shows all of this in a window with a fixture mode.

## 5. Trials

### 5.1 First launch with native discovery (plan trial 1): verified

- **Command:** in a subshell with every `TAILSCALE_*` and `TS_*` variable unset (none were set before clearing), `swift run --package-path Examples/StatusDemo StatusDemo` and `swift run --package-path Examples/PeerDiagnostics PeerDiagnostics --live --print`, each once without and once with `TAILSCALE_DISCOVERY_DEBUG=1` set inside the cleared subshell.
- **Discovery path:** the debug line was `[LocalAPIDiscovery] using macOS standalone pkg loopback port=<port>` (StatusDemo, synchronous discovery) and `[LocalAPIDiscovery] using standalone pkg loopback port=<port>` (Peer Diagnostics, `discoverAsync`). That is the standalone app's `/Library/Tailscale/ipnport` mechanism, not an override; no override line was printed.
- **Observed:** StatusDemo exited 0 and printed the daemon version (1.102.2), backend state `running`, this node, 11 peers, and 18 optional daemon features; its netcheck printed "no STUN responses (UDP blocked or empty DERP map)". Peer Diagnostics exited 0, connected over loopback with the token not shown, listed 11 peers (4 online), received an initial watch notification, and pinged an online macOS peer: "Reached directly via 203.0.113.10:41641 in 67.3 ms after 1 ping."
- **Permission prompt:** App Store discovery is off by default and was not enabled, so the code path that reads Group Containers did not run. No prompt could be seen because the Mac was at the login window; this record does not claim that none appeared.

### 5.2 Peer ping and watch (plan trial 2): verified, direct path only

- **Capture:** `python3 Scripts/capture-ping-fixture.py --peer <online peer> --type disco --name qualify-disco`, run from a copy of the script outside the repository so no fixture was added. One disco reply:

  ```json
  {"IP": "100.64.0.4", "NodeIP": "100.64.0.4", "NodeName": "example-peer", "Err": "",
   "LatencySeconds": 0.070376875, "Endpoint": "192.0.2.10:41641", "PeerRelay": "",
   "DERPRegionID": 0, "DERPRegionCode": ""}
  ```

- **Same reply, three classifications, all agree:**
  - Library: decoding that file with `JSONDecoder` into `PingResult` gave `path == .direct(endpoint: "192.0.2.10:41641")` and `isDirect == true` (a five-line consumer package depending on this checkout by path).
  - The official CLI's rule (`cmd/tailscale/cli/ping.go`: peer relay if `PeerRelay` is nonempty, else DERP if `DERPRegionID` is nonzero, else `Endpoint`): direct via the endpoint.
  - Both agree.
- **Back-to-back live pings:** `tailscale ping --c 1 <peer-ip>` printed `pong from example-peer (100.64.0.4) via 203.0.113.10:41641 in 109ms`; `tailscale-swift ping <peer-ip>` printed `ping 1: example-peer - 6.47 ms via 203.0.113.10:41641`; `tailscale-swift ping <peer-ip> --json` reported `Endpoint` set, `PeerRelay` empty, `DERPRegionID` 0. All three replies were direct. (The sanitizer maps every known address of a peer to one placeholder, so equal placeholders show both took a direct path, not that the endpoints were byte-identical.)
- **Watch:** `timeout 6 tailscale-swift watch` printed the connection line with daemon version 1.102.2, `State: Running`, `Health: OK`, and two engine-stats lines, then was stopped by the timeout (exit 124, as intended).
- **Live path kinds observed:** direct only. Peer relay, DERP, and unknown are tested from fixtures only.

### 5.9 Agent trial and independent consumer build by SHA: verified, with corrections needed

- **Prompt, in one sentence:** given only the published `llms.txt` and `Documentation/INTEGRATING.md` at `77fedf4`, build a consumer in an empty folder that displays a peer's last ping path and tests every path case, including unknown, without a daemon.
- **Result:** the agent resolved the package from GitHub by SHA (no path dependency; `Package.resolved` showed `77fedf49b5012ddb06dca63ead357853ad1fa32f` and swift-argument-parser 1.8.2), used public imports only and the `TailscaleClient` and `TailscaleClientMocks` products, and got 6 passing tests (direct, DERP, peer relay, unknown with zero-valued fields, unknown with fields absent, failed) in about 1.5 minutes, with one build iteration and no lookups beyond the two files.
- **Caveat:** it worked partly because the agent already knew the field names of Go's `ipnstate.PingResult`; the guide gave neither `PingResult`'s property names nor a ping JSON body. A developer without that knowledge would have had to read the sources.
- **Corrections it reported, checked against the source and made in this change:** list `latencySeconds`, `error`, and the `.derp` associated types; say a failed ping returns rather than throws and that `ping` defaults to `.disco`; show a complete ping body for `MockTransport` and which field selects each case; show the test target's two products and explain the mock closure's parameters; replace "zero-dependency" with what resolution fetches; put adding the dependency before the sample, with a clone step; state one Swift minimum (6.1); note the Unix socket path limit. Its remaining point, that `from: "1.0.0"` admits versions without `PingResult.path`, is resolved by the version bump that moves every documented pin together; the guide now marks the 1.1.0 additions.

## 7. Defects found and fixed during the 1.1.0 work

- Watches with default options were rejected with HTTP 400 by Tailscale 1.104 and later (#54).
- A rejected watch over the Unix socket hung silently until the daemon closed the connection (#53).
- A quiet watch over loopback ended after `requestTimeout` (30 s) with "The request timed out" (#58).
- Loopback connection failures were never classified as connect-stage, so watches and requests did not rediscover a restarted daemon (#60).
- Reconnecting watches ended on an undecodable line or their first reconnect, and did not rediscover a daemon on a new port or token (#48).
- `PingType.peerAPI` pings were never answered (#51).
- `PingResult.isDirect` was `true` for TSMP, ICMP, peerAPI, and failed pings (#51).
- A non-hermetic unit test ran real App Store discovery against the runner and hung the real-daemon lane's unit step until the job timeout (#52).
- Two nondeterministic tests: the generative JSON round-trip test (#57) and the discovery-recovery stress tests (#61, which also stops a straggler request from starting a second rediscovery).
- The release workflow would have failed its own docs check on the 1.1.0 preparation commit (#62).
- The examples did not build from a checkout whose folder was not named `swift-tailscale-client` (#50).
- In this change: the missing-socket recovery suggestion said App Store discovery happens on its own; CI cancelled in-progress runs on `main`; the guide's gaps from section 5.9; `llms.txt` and the agent skill said Linux connects to daemons.

## 8. Known limitations and untested

- **Live recovery:** no real daemon restart, disconnect, or profile switch (section 5.3).
- **Installations and callers:** the Mac App Store edition, sandboxed callers, and native Unix-socket discovery (section 5.4).
- **Logged-in Tailscale 1.104+:** every 1.104 run used a never-logged-in daemon, so peer-change notifications on 1.104 with real peers are unobserved. `IPNNotify` does not model the fields that replaced `NetMap`.
- **Path kinds:** only direct was observed live; peer relay, DERP, and unknown are fixture-tested.
- **Linux:** unqualified; not built or tested in required CI.
- **Long soaks:** the 1-hour and 24-hour soaks have still not been run.
- **Unary rediscovery over loopback** is shown only through error classification, not end to end.
- **Loopback watch lifetime:** `URLSession.shared` still ends a stream after 7 days (`timeoutIntervalForResource`); shown only with a short session value.
- **CI concurrency:** a `main` run that is waiting behind another can still be replaced by a newer one; only runs that have started are now kept.
- **After tagging:** the release workflow's publish step, Swift Package Index indexing and documentation, the Homebrew tap, resolution by tag, and pilot feedback.

The [roadmap's hardening list](../../ROADMAP.md#hardening) carries each follow-up.
